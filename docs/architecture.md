# Архитектура системы определения занятости парковочного места

## Обзор системы

Система определения занятости парковочного места работает на базе детекции объектов (YOLO) 
и геометрической логики пересечений. Ниже подробно описан весь пайплайн.

---

## 1. Детекция объектов (YOLO)

### 1.1. Что делает YOLO

YOLO (You Only Look Once) — это нейронная сеть для **object detection**. Она принимает 
изображение и возвращает список bounding box'ов (bbox) — прямоугольников, внутри которых 
обнаружены объекты определённых классов.

**Вход:** RGB-изображение (например, 640×480 пикселей)

**Выход:**
```
[
    (x1, y1, x2, y2, confidence, class_id),
    (x1, y1, x2, y2, confidence, class_id),
    ...
]
```

Где:
- `x1, y1` — координаты верхнего левого угла bbox
- `x2, y2` — координаты нижнего правого угла bbox
- `confidence` — уверенность сети (0.0 — 1.0)
- `class_id` — ID класса (COCO: 2=car, 0=person, 5=bus, 7=truck)

### 1.2. Порог уверенности (confidence threshold)

```
object_detected IF confidence >= CONFIDENCE_THRESHOLD
```

- **Высокий порог (0.5-0.7)** — меньше ложных срабатываний, но может пропускать 
  нечёткие/маленькие объекты
- **Низкий порог (0.15-0.3)** — ловит больше объектов, но больше шума

**Проблема бумажных макетов:** YOLO обучена на реальных фото автомобилей. Бумажная 
машинка может иметь confidence ~0.15-0.35, что ниже стандартного порога.

**Решение:** `CONFIDENCE_THRESHOLD = 0.25` — компромисс для демонстрации.

## 2. Определение парковочных зон

### 2.1. Геометрия зоны

Каждое парковочное место задаётся как:
- **Bounding box зоны:** `(z_x1, z_y1, z_x2, z_y2)` — прямоугольник
- **Точка номера:** `(label_x, label_y)` — координата номера места

### 2.2. Зачем точка номера

Вместо проверки пересечения всего bbox авто с зоной (что даёт ложные срабатывания при 
частичном входе), мы проверяем:

> **Место занято, если bbox обнаруженного объекта перекрывает точку номера**

Это более надёжный критерий, потому что:
1. Номер — это конкретная точка, а не вся зона
2. Если машина стоит на месте, она гарантированно закрывает номер
3. Если номер виден — место свободно (машины нет или она далеко)

---

## 3. Алгоритм определения занятости

### 3.1. Базовый алгоритм (точка номера)

Для каждого обнаруженного объекта `(bx1, by1, bx2, by2)` и каждой зоны с номером 
`(label_x, label_y)`:

```python
def is_zone_occupied(bbox, zone):
    """
    Проверить, перекрывает ли bbox точку номера зоны.
    
   bbox = (x1, y1, x2, y2, confidence)
    zone = (z_x1, z_y1, z_x2, z_y2, label_x, label_y)
    """
    margin = 5  # допуск в пикселях
    
    is_inside_x = (bbox.x1 - margin) <= zone.label_x <= (bbox.x2 + margin)
    is_inside_y = (bbox.y1 - margin) <= zone.label_y <= (bbox.y2 + margin)
    
    return is_inside_x and is_inside_y
```

**Логика:**
- Точка номера `(label_x, label_y)` находится внутри bbox?
- Если ДА → место занято
- Если НЕТ → место свободно

### 3.2. Альтернативный алгоритм (IoU — Intersection over Union)

Другой подход — вычислить процент пересечения bbox авто с зоной:

```python
def compute_iou(bbox_car, bbox_zone):
    """
    IoU = площадь_пересечения / площадь_объединения
    """
    # Площадь пересечения
    ix1 = max(car_x1, zone_x1)
    iy1 = max(car_y1, zone_y1)
    ix2 = min(car_x2, zone_x2)
    iy2 = min(car_y2, zone_y2)
    
    inter_area = max(0, ix2 - ix1) * max(0, iy2 - iy1)
    if inter_area == 0:
        return 0.0
    
    # Площадь объединения
    car_area = (car_x2 - car_x1) * (car_y2 - car_y1)
    zone_area = (zone_x2 - zone_x1) * (zone_y2 - zone_y1)
    union_area = car_area + zone_area - inter_area
    
    return inter_area / union_area
```

**Порог IoU:**
- IoU > 0.3 → место занято (значительное пересечение)
- IoU < 0.3 → место свободно

### 3.3. Альтернативный алгоритм (покрытие зоны)

```python
def coverage_percent(bbox_car, bbox_zone):
    """
    Какой процент зоны покрыт bbox автомобиля.
    """
    ix1 = max(car_x1, zone_x1)
    iy1 = max(car_y1, zone_y1)
    ix2 = min(car_x2, zone_x2)
    iy2 = min(car_y2, zone_y2)
    
    inter_area = max(0, ix2 - ix1) * max(0, iy2 - iy1)
    zone_area = (zone_x2 - zone_x1) * (zone_y2 - zone_y1)
    
    if zone_area == 0:
        return 0.0
    
    return inter_area / zone_area  # 0.0 — 1.0
```

**Порог покрытия:**
- > 50% → место занято
- 20-50% → возможно, частично
- < 20% → свободно

## 4. Проблема цвета и контрастности

### 4.1. Влияет ли цвет на детекцию?

**Напрямую — нет.** YOLO не использует пороговые значения цвета для принятия решения. 
Она обучена на миллионах изображений и распознаёт **паттерны** (формы, текстуры, 
контекст).

**Косвенно — да, влияет:**

| Фактор | Влияние |
|--------|---------|
| Цвет машины vs фон | Высокий контраст → легче детекция |
| Цвет бумаги vs фон | Низкий контраст → хуже детекция |
| Освещение | Тени/блики → ложные bbox или пропуски |
| Размытие | Расфокус → снижение confidence |

### 4.2. Почему бумажные машинки детектируются плохо

1. **YOLO обучена на реальных фото** — ожидает 3D-объекты, тени, перспективу
2. **Плоский рисунок** — нет глубины, теней, ожидаемой формы
3. **Размер** — маленькие объекты хуже детектируются (особенно на YOLOv8n)

### 4.3. Способы улучшить детекцию бумажных объектов

| Метод | Описание | Сложность |
|-------|----------|-----------|
| Снизить confidence threshold | `0.25` вместо `0.5` | ✅ Просто |
| Дообучить YOLO на бумажных авто | Fine-tuning с датасетом | 🔧 Средне |
| Использовать другой класс | `person` лучше детектится | ✅ Просто |
| Увеличить объекты | Подойти камерой ближе | ✅ Просто |
| Цветные объекты | Яркие машинки vs белый фон | ✅ Просто |

## 5. Сглаживание по времени (Temporal Smoothing)

### 5.1. Зачем нужно

Одиночные кадры могут давать:
- Ложные срабатывания (тень, блик, шум камеры)
- Пропуски (объект чуть не детектирован)

### 5.2. Алгоритм

```python
# История состояний за N последних кадров
history = [
    [True, False, True, ...],   # кадр N-2
    [True, True,  True, ...],   # кадр N-1
    [True, True,  False, ...],  # кадр N (текущий)
]

# Сглаживание: место занято, если >50% кадров оно было занято
for zone_idx in range(NUM_ZONES):
    occupied_count = sum(history[frame][zone_idx] for frame in history)
    zone_states[zone_idx] = occupied_count > len(history) / 2
```

**Параметр:** `SMOOTHING_FRAMES = 3` — последние 3 кадра.

## 6. Полный пайплайн системы

```
┌─────────────────────────────────────────────────────────────┐
│                     1. ЗАХВАТ КАДРА                          │
│   Веб-камера → numpy array (RGB, 640×480)                    │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                  2. ДЕТЕКЦИЯ ОБЪЕКТОВ (YOLO)                  │
│   Вход: RGB-изображение                                      │
│   Модель: yolov8n.pt (предобученная COCO)                    │
│   Порог: confidence >= 0.25                                  │
│   Классы: person, car, bus, truck                            │
│   Выход: [(x1,y1,x2,y2,conf), ...]                           │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│              3. ПРОВЕРКА ЗАНЯТОСТИ ЗОН                       │
│   Для каждой зоны:                                          │
│     occupied = False                                         │
│     Для каждой детекции:                                    │
│       Если bbox перекрывает точку номера → occupied = True   │
│                                                              │
│   Выход: [True, False, True, ...]  # состояние каждой зоны  │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                4. СГЛАЖИВАНИЕ (Temporal)                     │
│   История последних 3 кадров                                 │
│   Итог: зона занята, если >50% кадров занята                 │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                  5. ОТРИСОВКА РЕЗУЛЬТАТА                     │
│   - Зоны: зелёный = свободно, красный = занято               │
│   - Bbox детекций: синяя рамка + confidence                  │
│   - Счётчик: "Свободно: X/8 | Занято: Y/8"                  │
└─────────────────────────────────────────────────────────────┘
```

## 8. Рекомендации для НИРС (демонстрации)

### Что показать комиссии:

1. **Работающий пайплайн** — камера → YOLO → счётчик
2. **Визуализация** — зоны подсвечены, bbox нарисованы
3. **Реальное время** — обработка за <1 сек

### Как гарантировать результат:

1. **Крупные яркие объекты** — машинки должны быть >10% кадра
2. **Хорошее освещение** — без теней и бликов
3. **Подойти ближе** — камера ближе к парковке
4. **Добавить person** — люди детектируются лучше машин (класс 0)

### Если YOLO не видит бумажные машинки:

**Временное решение:** Положите на парковку **людей** (класс person) — YOLO детектит 
их с confidence 0.5-0.9. Для НИРС это демонстрирует **принцип работы системы**, даже 
если объекты не автомобили.

## 1. Введение

### 1.1 Цель работы

Целью данной работы является обучение нейросетевой модели на базе YOLOv8 для детекции объектов типа "Самолет", проведение модификации модели в соответствии с требованиями, а также сравнительный анализ результатов обучения различных модификаций на предмет качества и скорости работы.

### 1.2 Задачи

1. Подготовить датасет для распознавания объектов типа "Самолет" на основе COCO
2. Обучить модифицированные версии модели YOLOv8-nano
3. Провести сравнительный анализ качества и скорости работы
4. Экспортировать модели в формат ONNX для production использования
5. Обучить классификатор типов самолётов на базе ResNet18
6. Сделать выводы о влиянии модификаций на производительность

## 2. Методология

### 2.1 Датасет детектора

**Источник**: COCO 2017 dataset
**Класс**: airplane (category_id=5)
**Размер датасета**:

- Train: 97 изображений
- Val: 97 изображений
- Всего: 194 изображения

**Формат**: YOLO (txt аннотации с нормализованными координатами)

### 2.2 Датасет классификатора

**Источник**: FGVC Aircraft dataset
**Классы**: 100 типов самолётов (Boeing 737, Airbus A320, Cessna 172, и т.д.)
**Размер датасета**:

- Train: 6,667 изображений
- Val: 3,333 изображения
- Всего: 10,000 изображений

**Формат**: ImageFolder (директории по классам)

### 2.3 Архитектура моделей детектора

#### 2.3.1 Baseline модель

Базовая модель YOLOv8-nano без модификаций — стандартная архитектура Ultralytics.

**Параметры**:

- Слои: 23
- Детекторные головы: 3
- Размер: ~6MB (.pt), ~12MB (.onnx)
- Архитектура: стандартная YOLOv8n (CSPDarknet backbone + PANet/FPN neck + 3-head detect)

Обучались **два варианта baseline**:

1. **Baseline #1 (ab0b06ec)**: 100 эпох, batch=16, device=cpu
2. **Baseline #2 (ebba00ae)**: 200 эпох, batch=32, device=cpu

#### 2.3.2 Модификация 1 (mod1)

**Описание**: Удаление части 1 архитектуры (путь Upsample→Concat→C2f→Concat→C2f→Detect в Neck).

**Изменения**:

- Удалён верхний уровень FPN в Neck
- Оставлен только PANet путь для детекции
- Слои: 17
- Детекторные головы: 2

**Ожидаемый эффект**:

- Уменьшение размера модели
- Увеличение скорости инференса
- Возможное снижение точности на мелких объектах

#### 2.3.3 Модификация 2 (mod2)

**Описание**: Удаление частей 1, 2 и 3 архитектуры.

**Изменения**:

- Удалена часть 1 (Neck→Head путь)
- Удалена часть 2 (Conv в Neck)
- Удалена часть 3 (Conv→C2f в Backbone)
- Слои: 12
- Детекторные головы: 1

**Ожидаемый эффект**:

- Значительное уменьшение размера модели
- Максимальное увеличение скорости
- Более существенное снижение точности

### 2.4 Архитектура классификатора

**Модель**: ResNet18 (pretrained на ImageNet)
**Модификации**:

- Заменён последний FC слой для 100 классов
- Fine-tuning всех слоёв

## 4. Анализ результатов

### 4.1 Качество baseline vs модификации

**Главный результат**: Baseline #2 (200 эпох, batch=32) значительно превосходит все модификации по качеству:

| Метрика     | Baseline #2 | Mod1 (320px) | Mod2 (320px) |
| ----------- | ----------- | ------------ | ------------ |
| mAP50       | **0.9847**  | 0.7044       | 0.6899       |
| mAP50-95    | **0.9098**  | 0.4441       | 0.4116       |
| Precision   | **0.9928**  | 0.7870       | 0.7025       |
| Recall      | **0.9696**  | 0.6573       | 0.6084       |
| FPS (CPU)   | 76.70       | 118.43       | 114.88       |
| Размер (MB) | 11.58       | 11.89        | 2.29         |

**Интерпретация**:

1. **Baseline #2 обеспечивает хорошую детекцию** (mAP50=0.9847, Precision=0.9928)
2. **Mod1 теряет 28% качества** по mAP50, но на 54% быстрее (118 vs 76 FPS)
3. **Mod2 теряет 30% качества** по mAP50, но на 50% быстрее и в 5 раз меньше
4. **Компромисс**: -28-30% качества за +50-55% скорости

### 4.2 Влияние количества эпох и batch size

Сравнение Baseline #1 (100 эпох, batch=16) vs Baseline #2 (200 эпох, batch=32):

| Метрика   | Baseline #1 | Baseline #2 | Улучшение |
| --------- | ----------- | ----------- | --------- |
| mAP50     | 0.9650      | 0.9847      | +2.0%     |
| mAP50-95  | 0.8494      | 0.9098      | +7.1%     |
| Precision | 0.9854      | 0.9928      | +0.7%     |
| Recall    | 0.9436      | 0.9696      | +2.8%     |

**Вывод**: Увеличение epochs с 100 до 200 и batch с 16 до 32 даёт:

- Значительное улучшение mAP50-95 (+7.1%) — лучшая локализация объектов
- Меньшее но заметное улучшение mAP50 (+2.0%)
- Recall улучшился на 2.8% — меньше пропущенных объектов

### 4.3 Влияние размера изображения

**Ключевое наблюдение**: Увеличение разрешения с 160px до 320px привело к значительному улучшению качества:

- **Mod1**: mAP50 вырос с ~0.56 до 0.7044 (+25.6%)
- **Mod2**: mAP50 вырос с 0.5605 до 0.6899 (+23.1%)

**Объяснение**:

- Более высокое разрешение позволяет модели лучше различать мелкие детали самолётов
- Улучшается локализация объектов (mAP50-95 вырос на ~20-25%)
- Recall увеличился на ~30%, что означает меньше пропущенных объектов

**Baseline** обучалась только на 320px, но показала mAP50=0.9847 — это на 40% лучше чем Mod1 (320px).

- **Применение**: Обработка множества видеопотоков, real-time системы с высокой нагрузкой

**Real-time видео системы**:

- Детектор: Baseline #2 (320px) для качества или Mod1 (320px) для баланса
- 76.70 FPS (Baseline) позволяет обрабатывать до 2 потоков 30 FPS параллельно
- 118.43 FPS (Mod1) позволяет обрабатывать до 4 потоков 30 FPS параллельно

## 6. Заключение

В рамках данной работы были успешно обучены **две baseline модели YOLOv8-nano**, две модификации (Mod1 и Mod2) для детекции самолётов и классификатор ResNet18 для определения типов самолётов. 

**Baseline #2** (200 эпох, batch=32, 320px) показал **наилучшие результаты по качеству** — mAP50=0.9847, mAP50-95=0.9098, Precision=0.9928, Recall=0.9696. Это практически идеальная детекция для данного датасета. Однако она работает на CPU и имеет скорость 76.70 FPS.

**Модификация 1** (320px, GPU) показала **лучший баланс качества и скорости** — mAP50=0.7044 при 118.43 FPS на CPU. Это на 40% хуже Baseline #2 по качеству, но на 54% быстрее. Mod1 рекомендуется для production систем где важен баланс точности и производительности.

**Модификация 2** (320px, GPU) демонстрирует **минимальный размер модели** — всего 2.29 MB (в 5.2 раза меньше чем Baseline), при приемлемом качестве mAP50=0.6899 и скорости 114.88 FPS. Это делает её идеальной для edge устройств с ограниченной памятью, IoT и мобильных приложений.

**Классификатор ResNet18** успешно различает 100 типов самолётов с точностью 85.24%, что позволяет создать полноценный pipeline детекции и классификации.

**Ключевые результаты:**

1. **Качество**: Baseline #2 (200 эпох) значительно превосходит модификации — mAP50=0.9847 vs 0.7044 (Mod1) и 0.6899 (Mod2). Увеличение epochs с 100 до 200 и batch с 16 до 32 даёт +2% по mAP50 и +7% по mAP50-95.
2. **Скорость инференса**: Mod2 (160px) — самая быстрая модель (127.22 FPS), Baseline (320px) — 76.70 FPS, Mod1 (320px) — 118.43 FPS (лучший баланс)
3. **Размер модели**: Mod2 в 5.2 раза меньше Baseline/Mod1 (2.29 MB vs 11.58-11.89 MB) — критично для edge устройств
4. **Компромисс**: Mod1 теряет 40% качества по сравнению с Baseline, но на 54% быстрее. Mod2 теряет 30% качества, но в 5 раз меньше и на 50% быстрее.
5. **Разрешение**: Увеличение с 160px до 320px даёт прирост ~25% по mAP50 для модификаций

Проект демонстрирует, что для задачи детекции самолётов **Baseline #2 (200 эпох, 320px) является оптимальным выбором для приложений где критично качество**, а **Mod1 (320px) — лучший баланс для production**. Для устройств с ограниченной памятью рекомендуется Mod2 (320px), а для систем с высокой нагрузкой — Mod2 (160px) с максимальной скоростью.
